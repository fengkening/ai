## 一、工作约定（用户设定，优先级最高）

1. **先读后动**：任何改动前，先读本文件。
2. **小步确认**：每完成一个小功能，先让用户确认，再用 Git 存一次档。
3. **未存档不重构**：没有存档点之前，不做大改。
4. **媒体文件不进 Git**：图片、音频、视频一律不入库。仓库未加 `.gitignore`，靠人工把关。
5. **一次存档一件事**：一个 commit 对应一个已确认的小功能，提交信息写清"做了什么"。

## 二、已定决策

### D-001 模板语言用 Go

- **日期**：2026-10-25
- **背景**：手机容器里没有 gcc / make，本地编译不了任何东西；需要"云端编译、手机运行"。
- **决定**：模板主程序用 Go，靠 `GOOS` / `GOARCH` 交叉编译。
- **后果**：产物是静态二进制，Android 容器里可直接执行；CI 不需要装交叉工具链。
- **代价**：将来若要做 C/C++ 项目，得另加 `gcc-aarch64-linux-gnu` 的构建分支。

### D-002 git 对象库与工作区分离

- **日期**：2026-10-25
- **背景**：`/sdcard` 是 FUSE 挂载，**不支持硬链接**。git 写入对象时报
  `unable to rename temporary '*.pack'`，`clone` / `fetch` 反复重试均失败。
- **决定**：工作区保留在 `/sdcard/dsh/ai`，对象库放 `/root/work/ai.git`
  （`git init --separate-git-dir`）。
- **后果**：代码文件在手机存储里可见可改；`.git` 只是一个指针文件
  （`gitdir: /root/work/ai.git`）。
- **代价**：仓库目录不能整体拷走，迁移需 `git bundle` 或重新 clone。

### D-003 发版走 tag 触发 + gh release

- **日期**：2026-10-25
- **背景**：需要一条固定的"打标签即发版"路径。
- **决定**：`.github/workflows/release.yml` 在推送 `v*` 标签时编译并发布；
  `workflow_dispatch` 手动触发只编译、不发版。
- **后果**：发版动作 = `git tag vX.Y.Z && git push origin vX.Y.Z`。

### D-004 二进制产物不进仓库

- **日期**：2026-10-25
- **背景**：arm64 / amd64 产物各约 1.3 MB，入库会让历史无谓膨胀。
- **决定**：产物由 Actions 上传为 release 附件，附带 `SHA256SUMS.txt`；仓库只存源码。
- **后果**：取用方式是 `gh release download`，不是 `git clone`。

## 三、环境事实（排障用）

- `github.com` 链路不稳：偶发 `GnuTLS recv error (-110)`、`ECONNRESET`、连接超时，
  重跑即可；`api.github.com` 稳定，所以 `gh` 类命令基本不受影响。
- 推送 `.github/workflows/` 需要 token 带 `workflow` scope，否则被拒。
- 长轮询（如设备码换取 token）不要用裸 `nohup`，进程活不过回合边界；用后台任务承载。
